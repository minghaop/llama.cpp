Model Preparer Pro API¶

PyTorch Model Preparer Pro API automates model definition changes and generates a new PyTorch model which more closely matches how QAIRT would view the model when running on target. It replaces functionals and reused modules in the model with independent modules in accordance with the PyTorch model guidelines which AIMET requires.

In addition, there are occasions when QAIRT will group a subset of modules together as one module, or split a module into a subset of modules. In such cases, Model Preparer Pro provides a new model with these same groupings in mind, such that when quantizing the prepared model, the locations where noise is simulated more closely matches where quantization would take place on target.

In case ‘return_prepare_model’ is passed as True in the API, an IR aligned pytorch model is returned. By default, path of prepared model prepared model definition file and path of its state-dict file is returned from the API. Apart from this, this API also saves the following files on disk.

  • a .py file containing the prepared model definition

  • a .safetensor file containing corresponding weights and metadata

  • a .dlc file which will be used to generate a quantized dlc.

These files can be found under the path given to the call to prepare_model.

The .py and .safetensor files contain everything that is needed to instantiate a prepared version of the original models, and do not depend on any of the original model’s dependencies except for torch and torchvision

Usage Guidelines¶

  • As the model preparation depends on the QAIRT version being run, if users prepare models and save the generated .py and .safetensor files, these should only be used in pipelines which will later use the same QAIRT version to bring the model onto target. If the QAIRT version is changed, users should again bring their original model through Model Preparer Pro once more, making sure the new QAIRT version is also used.

  • If the user saves the prepared model returned from prepare_model() API using torch.save(), in order to restore the model with torch.load(), ensure that the exported model definition .py file is present either in the same directory as the script calling torch.load(), or in the PYTHONPATH.

  • Dynamic flows will not be preserved. Whichever branches are taken with the dummy input that is passed in will be the only parts of the model that remain in the prepared model.

  • The prepared model expects input tensors in the same shapes and dimensions as the dummy input used to prepare the model, except for the batch dimension which can remain variable.

  • If the original model had multiple nested inputs or nested outputs, all inputs and outputs will be flattened in the prepared model. For example, say the inputs to the model come in the form inp_0, (inp_1, (inp_2, inp_3)), (inp_4, inp_5). The inputs to the prepared model will be flattened into one level: inp_0, inp_1, inp_2, inp_3, inp_4, inp_5.

    Note that with the previous guideline, the shapes and number of dimensions for corresponding inputs must remain the same. E.g. inp_0 in original model vs. inp_0 in prepared model, inp_1 to inp_1, etc.

    Note: Experimental support has been added to allow nested outputs. To enable this, pass

    order_outputs = True in the API

  • Model Preparer Pro relies on being able to flexibly change model device using torch.to(torch.device)). The original model should not be taking device decisions by itself within the forward pass.

  • The Model Preparer Pro API requires minimum PyTorch 1.9 version.

Top-level API¶

qti.aisw.preparer_api.model_preparer.prepare_model(model: torch.nn.Module,
              dummy_input: Union[torch.Tensor, Tuple],
              path: str = './',
              filename: str = 'converted_model',
              model_name: str = 'ConvertedModel',
              input_names: Optional[List[str]] = None,
              output_names: Optional[List[str]] = None,
              skipped_optimizers: Optional[List[str]] = None,
              keep_linear_without_bias: bool = False,
              onnx_export_args: Optional[Dict] = None,
              converter_args: Optional[Dict] = None,
              block_names: Optional[List[str]] = None,
              keep_original_model: bool = True,
              order_inputs: bool = False,
              order_outputs: bool = False,
              keep_original_model_structure: bool = False,
              custom_op_info: CustomOpInfo = None,
              return_prepare_model: bool = False) -> Optional[Union[torch.nn.Module, Tuple]]:

API to prepare model by taking in the starting model, converting to IR graph, and rebuilding a new pytorch model. This API writes out the prepared model definition, weights to output files and serialized float dlc file in the given path location. If return_prepare_model is True, it returns preparer model otherwise returns path of model definition(.py) and weight file(.safetensor).

Parameters

  • model: Model to prepare

  • dummy_input: Dummy input(s) to the model

  • path: Path to save converted model definition

  • filename: Filename to save converted model definition

  • model_name: Name of the converted model

  • input_names: Input names to use for the model which appear in the prepared model inputs

  • output_names: Output names to use for the model which appear in the onnx model exported during model prepare

  • skipped_optimizers: Optimizer names to disable during onnx simplification

  • keep_linear_without_bias: QAIRT usually converts Linear(…,bias=False) to MatMul operation if this variable is set True, preparer pro will try to keep original Linear to Linear not MatMul

  • onnx_export_args: Optional export arguments for torch onnx export. Can come in the form of a dictionary.

  • converter_args: Optional argument with QAIRT converter specific overrides

  • block_names: Block names to extract separate torch.nn.Module

  • keep_original_model: Flag to keep original model, and not move model to meta device. If this flag is set to False, the original model is no longer avalible for reference.

  • order_inputs: Flag to order input of prepared model in accordance with source model.

  • order_outputs: Flag to order output of prepared model in accordance with source model.

  • keep_original_model_structure: Flag for keeping original model structure in prepared model

  • custom_op_info: DataClass consisting of op_type_to_module mapping and custom_module_paths

  • return_prepare_model: Flag to return prepared model after loading or not.

Return type:

  • Optional[Union[torch.nn.Module, Tuple]]

Return

  • Converted pytorch model if return_prepare_model is True else path of model definition( .py) and weight file(.safetensor).

Code Examples¶

Required imports

import torch
import torch.nn.functional as F

from qti.aisw.preparer_api.model_preparer import prepare_model
from qti.aisw.tools.core.modules.light_weight_quantizer.lwq_module import (LightWeightQuantizerInputConfig,QAIRTLightWeightQuantizer)

Example 1: Model with Functional relu

We begin with the following model, which contains two functional relus and relu method inside forward method.

class ModelWithFunctionalReLU(torch.nn.Module):
    """ Model that uses functional ReLU instead of nn.Modules. Expects input of shape (1, 3, 32, 32) """
    def __init__(self):
        super(ModelWithFunctionalReLU, self).__init__()
        self.conv1 = torch.nn.Conv2d(3, 6, 5)
        self.conv2 = torch.nn.Conv2d(6, 16, 5)
        self.fc1 = torch.nn.Linear(9216, 128)
        self.fc2 = torch.nn.Linear(128, 10)

    def forward(self, x):
        x = F.relu(self.conv1(x))
        x = F.relu(self.conv2(x))
        x = torch.flatten(x, 1)
        x = F.relu(self.fc1(x))
        x = self.fc2(x).relu()
        return x

Run Model Preparer Pro on the model by passing in the model.

def model_preparer_functional_example():

    # Load the model and keep in eval() mode
    model = ModelWithFunctionalReLU().eval()
    input_shape = (1, 3, 32, 32)
    input_tensor = torch.randn(*input_shape)

    # Call to prepare_model API
    prepared_model = prepare_model(model=model,
                                   dummy_input=input_tensor,
                                   path='/tmp',
                                   return_prepare_model=True)
    print(prepared_model)

    # ConvertedModel(
    # (conv1_Conv): Conv2d(3, 6, kernel_size=(5, 5), stride=(1, 1))
    # (Relu): ReLU()
    # (conv2_Conv): Conv2d(6, 16, kernel_size=(5, 5), stride=(1, 1))
    # (Relu_1): ReLU()
    # (fc1_Gemm): Linear(in_features=9216, out_features=128, bias=True)
    # (Relu_2): ReLU()
    # (fc2_Gemm): Linear(in_features=128, out_features=10, bias=True)
    # (Relu_3): ReLU()
    # )

    # Compare the outputs of original and transformed model
    assert torch.allclose(model(input_tensor), prepared_model(input_tensor))

    # below is needed to keep above commented lines visible
    print('Done')

The prepared_model that is returned is functionally same as original model. This can be verified by comparing the outputs of both models. The prepared_model will have all three functional relus now converted to torch.nn.ReLU modules satisfying the model guidelines linked above.

Export to Quantized DLC¶

Using the .dlc file generated during the prepare_model step, user can generate the quantized DLC file which can be directly executed on target. To be able to use the export to dlc feature, user is required to use LightWeightQuantizerInputConfig and QAIRTLightWeightQuantizer from qti.aisw.tools.core.modules.light_weight_quantizer.lwq_module

The input config to the QAIRTLightWeightQuantizer() is defined by: qti.aisw.tools.core.modules.light_weight_quantizer.lwq_module.LightWeightQuantizerInputConfig class

Parameters of LightWeightQuantizerInputConfig

  • path: Path of the directory to save exported DLC file.

  • filename_prefix: Filename to save exported DLC file with. The file will end in .dlc extension

  • dlc_path: FilePath Path to the input DLC file generated during model preparation.

  • weight_file_path: Path to weight file in safetensors file.

  • encoding_path: Encoding file path. This contains the encoding to be applied on ir_graph.

  • quantize_dlc: True if the exported dlc should be quantized, False otherwise

  • activation_bitwidth: Activation bw to be used to quantized scalar values.

  • float_bias_bitwidth: Float bias bitwidth, 0, 16 or 32 (default 32)

Example 2: Prepare Model, Quantize and Export to dlc
