Execution on QNX¶

Running the HTP Backend on a QNX target is largely similar to running the CPU and GPU backend on QNX target.

In automotive application, QNN’s serialized binary context should be used for HTP backend execution. To generate the context run:

$ ${QNN_SDK_ROOT}/bin/x86_64-linux-clang/qnn-context-binary-generator \
    --backend ${QNN_SDK_ROOT}/lib/x86_64-linux-clang/libQnnHtp.so \
    --model ${QNN_SDK_ROOT}/examples/Models/InceptionV3/model_libs/x86_64-linux-clang/libInception_v3_quantized.so \
    --binary_file Inception_v3_quantized.serialized

This creates the context at:

  • ${QNN_SDK_ROOT}/examples/Models/InceptionV3/output/Inception_v3_quantized.serialized.bin

You will need a FTP client like FileZilla to transfer files from host machine to the target, please make sure the file transfer type is set to binary.

Now telnet to the QNX terminal (ensure the devices has Telnet service running) and create directories:

telnet 192.168.1.1 # telnet <device-ip>

Trying 192.168.1.1...
Connected to 192.168.1.1.

QNX Neutrino (localhost) (ttyp6)
login: root
Logging in with home = "/".

$ mkdir -p /data/local/tmp/lib
$ mkdir -p /data/local/tmp/bin

FTP the necessary libraries to device:

${QNN_SDK_ROOT}/lib/aarch64-qnx/libQnnHtp.so to /data/local/tmp/lib
${QNN_SDK_ROOT}/bin/aarch64-qnx/qnn-net-run to /data/local/tmp/bin
${QNN_SDK_ROOT}/bin/aarch64-qnx/qnn-profile-viewer to /data/local/tmp/bin

# For SA8295 and SA8540:
${QNN_SDK_ROOT}/lib/aarch64-qnx/libQnnHtpV68Stub.so to /data/local/tmp/lib

# For SA8650 and SA8775:
${QNN_SDK_ROOT}/lib/aarch64-qnx/libQnnHtpV73Stub.so to /data/local/tmp/lib

In the QNX terminal, enable permissions for QNN binaries:

$ chmod 777 /data/local/tmp/bin/qnn-net-run
$ chmod 777 /data/local/tmp/bin/qnn-profile-viewer

Then FTP the following library to target’s CDSP directories:

# For SA8295 and SA8540:
${QNN_SDK_ROOT}/lib/hexagon-v68/unsigned/libQnnHtpV68Skel.so to /mnt/etc/images/cdsp0/
${QNN_SDK_ROOT}/lib/hexagon-v68/unsigned/libQnnHtpV68Skel.so to /mnt/etc/images/cdsp1/  #For CDSP1

# For SA8650 with /dspfw and /dsplib partitions and for SA8775:
${QNN_SDK_ROOT}/lib/hexagon-v73/unsigned/libQnnHtpV73Skel.so to /mnt/etc/images/dsp/

# For SA8650 without /dspfw and /dsplib partitions:
${QNN_SDK_ROOT}/lib/hexagon-v73/unsigned/libQnnHtpV73Skel.so to /mnt/etc/images/cdsp0/
${QNN_SDK_ROOT}/lib/hexagon-v73/unsigned/libQnnHtpV73Skel.so to /mnt/etc/images/cdsp1/  #For CDSP1

Next, for SA8540, FTP non-FuSa CDSP images to /mnt/etc/images/:

# For CDSP0:
${QNX_Build_Path}/qnx_ap/prebuilt_NHLOS/cdsp0_adas/non_fusa/asic_8540/cdsp0.mbn to /mnt/etc/images/
${QNX_Build_Path}/qnx_ap/prebuilt_NHLOS/cdsp0_adas/non_fusa/asic_8540/cdsp0.mdt to /mnt/etc/images/
${QNX_Build_Path}/qnx_ap/prebuilt_NHLOS/cdsp0_adas/non_fusa/asic_8540/shared_obj/fastrpc_shell_3 to /mnt/etc/images/
${QNX_Build_Path}/qnx_ap/prebuilt_NHLOS/cdsp0_adas/non_fusa/asic_8540/shared_obj/fastrpc_shell_unsigned_3 to /mnt/etc/images/

# For CDSP1:
${QNX_Build_Path}/qnx_ap/prebuilt_NHLOS/cdsp1_adas/non_fusa/asic_8540/cdsp1.mbn to /mnt/etc/images/
${QNX_Build_Path}/qnx_ap/prebuilt_NHLOS/cdsp1_adas/non_fusa/asic_8540/cdsp1.mdt to /mnt/etc/images/
${QNX_Build_Path}/qnx_ap/prebuilt_NHLOS/cdsp1_adas/non_fusa/asic_8540/shared_obj/fastrpc_shell_4 to /mnt/etc/images/
${QNX_Build_Path}/qnx_ap/prebuilt_NHLOS/cdsp1_adas/non_fusa/asic_8540/shared_obj/fastrpc_shell_unsigned_4 to /mnt/etc/images/

Now FTP the input data, input lists and serialized bin to device:

${QNN_SDK_ROOT}/examples/Models/InceptionV3/data/cropped to /data/local/tmp/bin
${QNN_SDK_ROOT}/examples/Models/InceptionV3/data/target_raw_list.txt to /data/local/tmp/bin
${QNN_SDK_ROOT}/examples/Models/InceptionV3/output/Inception_v3_quantized.serialized.bin to /data/local/tmp/bin

Finally, reset the target with the following command in the QNX terminal:

$ reset

Now, qnn-net-run and qnn-profile-viewer can be executed using HTP and QNX. Telnet into the QNX terminal and setup the execution environment:

$ cd /data/local/tmp/bin
$ export PATH=/data/local/tmp/bin:$PATH
$ export VENDOR_LIB=/data/local/tmp/lib
$ export LD_LIBRARY_PATH=$VENDOR_LIB:$LD_LIBRARY_PATH
$ export ADSP_LIBRARY_PATH="/mnt/etc/images/cdsp0;$VENDOR_LIB"

Then we can execute qnn-net-run with the following:

$ ./qnn-net-run \
    --backend libQnnHtp.so \
    --input_list target_raw_list.txt \
    --retrieve_context Inception_v3_quantized.serialized.bin

We can also execute qnn-net-run with profiling:

$ ./qnn-net-run \
    --backend libQnnHtp.so \
    --input_list target_raw_list.txt \
    --retrieve_context Inception_v3_quantized.serialized.bin \
    --profiling_level basic

# OR

$ ./qnn-net-run \
    --backend libQnnHtp.so \
    --input_list target_raw_list.txt \
    --retrieve_context Inception_v3_quantized.serialized.bin \
    --profiling_level detailed

Profiling data can be viewed using qnn-profile-viewer by running the following command:

$ ./qnn-profile-viewer \
    --input_log output/qnn-profiling-data.log

Outputs from the run will be located at the default ./output directory. Exit the device and view the results:

$ exit
$ cd ${QNN_SDK_ROOT}/examples/Models/InceptionV3
$ mkdir output_qnx

Finally, FTP /data/local/tmp/bin/output to ${QNN_SDK_ROOT}/examples/Models/InceptionV3/output_qnx and run the following:

$ python3 ${QNN_SDK_ROOT}/examples/Models/InceptionV3/scripts/show_inceptionv3_classifications.py \
    -i data/cropped/raw_list.txt \
    -o output_qnx/ \
    -l data/imagenet_slim_labels.txt

Execution on LA (Android)¶

In automotive application, QNN’s serialized binary context should be used for HTP backend execution. To generate the context run:

$ ${QNN_SDK_ROOT}/bin/x86_64-linux-clang/qnn-context-binary-generator \
    --backend ${QNN_SDK_ROOT}/lib/x86_64-linux-clang/libQnnHtp.so \
    --model ${QNN_SDK_ROOT}/examples/Models/InceptionV3/model_libs/x86_64-linux-clang/libInception_v3_quantized.so \
    --binary_file Inception_v3_quantized.serialized

This creates the context at:

  • ${QNN_SDK_ROOT}/examples/Models/InceptionV3/output/Inception_v3_quantized.serialized.bin

Now execute adb root && adb remount for your target, adb shell to the QNN terminal and create directories:

$ mkdir -p /data/local/tmp/lib
$ mkdir -p /data/local/tmp/bin

Push the necessary libraries to device:

$ adb push ${QNN_SDK_ROOT}/lib/aarch64-android/libQnnHtpV68Stub.so /data/local/tmp/lib
$ adb push ${QNN_SDK_ROOT}/lib/aarch64-android/libQnnHtp.so /data/local/tmp/lib
$ adb push ${QNN_SDK_ROOT}/bin/aarch64-android/qnn-net-run /data/local/tmp/bin
$ adb push ${QNN_SDK_ROOT}/bin/aarch64-android/qnn-profile-viewer /data/local/tmp/bin

In the LA GVM terminal, enable permissions for QNN binaries:

$ chmod 777 /data/local/tmp/bin/qnn-net-run
$ chmod 777 /data/local/tmp/bin/qnn-profile-viewer

Push the HTP backend binary to the target:

$ adb push ${QNN_SDK_ROOT}/lib/hexagon-v68/unsigned/libQnnHtpV68Skel.so /data/local/tmp/lib

Next, connect to QNX via FTP and pull the following files from the /mnt/etc/images/cdsp0 directory:

libc++.so.1
libc++abi.so.1

Then, transfer these files to the /data/local/tmp/lib directory on the target device:

$ adb push libc++.so.1 /data/local/tmp/lib
$ adb push libc++abi.so.1 /data/local/tmp/lib

Now push the input data, input lists and serialized bin to device:

$ adb push ${QNN_SDK_ROOT}/examples/Models/InceptionV3/data/cropped /data/local/tmp/bin
$ adb push ${QNN_SDK_ROOT}/examples/Models/InceptionV3/data/target_raw_list.txt /data/local/tmp/bin
$ adb push ${QNN_SDK_ROOT}/examples/Models/InceptionV3/output/Inception_v3_quantized.serialized.bin /data/local/tmp/bin

Finally, reset the target with the following command in the LA GVM terminal:

$ reset

Now qnn-net-run and qnn-profile-viewer can be executed using HTP and LA GVM. Then, adb shell into the LA GVM terminal and setup the execution environment:

$ cd /data/local/tmp/bin
$ export PATH=/data/local/tmp/bin:$PATH
$ export VENDOR_LIB=/data/local/tmp/lib
$ export LD_LIBRARY_PATH=$VENDOR_LIB:$LD_LIBRARY_PATH
$ export ADSP_LIBRARY_PATH="/vendor/lib/rfsa/adsp;$VENDOR_LIB;"

Then we can execute qnn-net-run with the following:

$ ./qnn-net-run \
    --backend libQnnHtp.so \
    --input_list target_raw_list.txt \
    --retrieve_context Inception_v3_quantized.serialized.bin

We can also execute qnn-net-run with profiling:

$ ./qnn-net-run \
    --backend libQnnHtp.so \
    --input_list target_raw_list.txt \
    --retrieve_context Inception_v3_quantized.serialized.bin \
    --profiling_level basic

# OR

$ ./qnn-net-run \
    --backend libQnnHtp.so \
    --input_list target_raw_list.txt \
    --retrieve_context Inception_v3_quantized.serialized.bin \
    --profiling_level detailed

Profiling data can be viewed using qnn-profile-viewer by running the following command:

$ ./qnn-profile-viewer \
    --input_log output/qnn-profiling-data.log

Outputs from the run will be located at the default ./output directory. Exit the device and view the results:

$ exit
$ cd ${QNN_SDK_ROOT}/examples/Models/InceptionV3
$ adb pull /data/local/tmp/bin/output output_android
$ python3 ${QNN_SDK_ROOT}/examples/Models/InceptionV3/scripts/show_inceptionv3_classifications.py \
    -i data/cropped/raw_list.txt \
    -o output_android/ \
    -l data/imagenet_slim_labels.txt
