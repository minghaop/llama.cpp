Execution on QNX¶

Before proceeding, ensure that the QNN SDK environment is properly configured by following the instructions in the Setup guide. Next, complete the initial model configuration as outlined in the Model Initial Setup. Once the setup is complete, proceed with the following steps to continue with the example workflow.

Note

  • ANDROID_NDK_ROOT is not necessary here

Setup the QNX environment by defining the environment variables on your local PC:

export QNX_HOST=<QNX_Toolchain_Location>/host/linux/x86_64/
export QNX_TARGET=<QNX_Toolchain_Location>/target/
export PATH=$QNX_HOST/usr/bin:$PATH

When using qnn-mode-lib-generator to build your model, use additional argument -t aarch64-qnx:

$ ${QNN_SDK_ROOT}/bin/x86_64-linux-clang/qnn-model-lib-generator \
    -c ${QNN_SDK_ROOT}/examples/Models/InceptionV3/model/Inception_v3.cpp \
    -b ${QNN_SDK_ROOT}/examples/Models/InceptionV3/model/Inception_v3.bin \
    -o ${QNN_SDK_ROOT}/examples/Models/InceptionV3/model_libs \ # This can be any path
    -t aarch64-qnx

This will produce the following artifacts:

${QNN_SDK_ROOT}/examples/Models/InceptionV3/model_libs/aarch64-qnx/libInception_v3.so

You will need a FTP client like FileZilla to transfer files from host machine to the target, please make sure the file transfer type is set to binary.

Now telnet to the QNX terminal (ensure the devices has Telnet service running) and create directories:

telnet 192.168.1.1 # telnet <device-ip>

Trying 192.168.1.1...
Connected to 192.168.1.1.

QNX Neutrino (localhost) (ttyp6)
login: root
Logging in with home = "/".

$ mkdir -p /data/local/tmp/lib
$ mkdir -p /data/local/tmp/bin

FTP the necessary libraries to device:

${QNN_SDK_ROOT}/lib/aarch64-qnx/libQnnCpu.so to /data/local/tmp/lib
${QNN_SDK_ROOT}/bin/aarch64-qnx/qnn-net-run to /data/local/tmp/bin
${QNN_SDK_ROOT}/bin/aarch64-qnx/qnn-profile-viewer to /data/local/tmp/bin

In the QNX terminal, enable permissions for QNN binaries:

$ chmod 777 /data/local/tmp/bin/qnn-net-run
$ chmod 777 /data/local/tmp/bin/qnn-profile-viewer

Now FTP the input data, input lists and model library to device:

${QNN_SDK_ROOT}/examples/Models/InceptionV3/data/cropped to /data/local/tmp/bin
${QNN_SDK_ROOT}/examples/Models/InceptionV3/data/target_raw_list.txt to /data/local/tmp/bin
${QNN_SDK_ROOT}/examples/Models/InceptionV3/model_libs/aarch64-qnx/libInception_v3.so to /data/local/tmp/bin

Finally, reset the target with the following command in the QNX terminal:

$ reset

Now qnn-net-run and qnn-profile-viewer can be executed using CPU and QNX. Then, telnet into the QNX terminal and set up the execution environment:

$ cd /data/local/tmp/bin
$ export PATH=/data/local/tmp/bin:$PATH
$ export VENDOR_LIB=/data/local/tmp/lib
$ export LD_LIBRARY_PATH=$VENDOR_LIB:$LD_LIBRARY_PATH

Then we can execute qnn-net-run with the following:

$ ./qnn-net-run \
    --backend libQnnCpu.so \
    --input_list target_raw_list.txt \
    --model libInception_v3.so

We can also execute qnn-net-run with profiling:

$ ./qnn-net-run \
    --backend libQnnCpu.so \
    --input_list target_raw_list.txt \
    --model libInception_v3.so \
    --profiling_level basic

# OR

$ ./qnn-net-run \
    --backend libQnnCpu.so \
    --input_list target_raw_list.txt \
    --model libInception_v3.so \
    --profiling_level detailed

Profiling data can be viewed using qnn-profile-viewer by running the following command:

$ ./qnn-profile-viewer \
    --input_log output/qnn-profiling-data.log

Outputs from the run will be located at the default ./output directory. Exit the device and view the results:

$ exit
$ cd ${QNN_SDK_ROOT}/examples/Models/InceptionV3
$ mkdir output_qnx

Finally, FTP /data/local/tmp/bin/output to ${QNN_SDK_ROOT}/examples/Models/InceptionV3/output_qnx and run the following:

$ python3 ${QNN_SDK_ROOT}/examples/Models/InceptionV3/scripts/show_inceptionv3_classifications.py
    -i data/cropped/raw_list.txt \
    -o output_qnx/ \
    -l data/imagenet_slim_labels.txt
