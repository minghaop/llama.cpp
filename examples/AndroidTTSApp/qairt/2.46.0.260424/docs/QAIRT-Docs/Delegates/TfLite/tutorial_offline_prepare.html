Tutorial - Running Offline Prepare Using the |Qualcomm(R)| AI Engine Direct Delegate¶

Consider that the initialization time of a model can be long. Users application might not be able to address that long latency. While we have caching mechanism, it still requires a device and still cause a long latency at 1st run. Therefore, we prepare the “cache” on x86 host before deploying models to a device.

This tutorial demonstrates how to generate the cache for the TFLite inception_v3_quant model using the |Qualcomm(R)| AI Engine Direct Delegate on x86 host.

Prerequisites¶

The following list of prerequisites must be met before starting this tutorial:

  1. Read the Overview and Setup pages to understand the different components of the |Qualcomm(R)| AI Engine Direct Delegate SDK.

  2. Read the Tutorial for qtld-net-run pages to understand how to run the model using |Qualcomm(R)| AI Engine Direct Delegate.

Setup¶

This tutorial will use the same inception_v3_quant model used in Tutorial for qtld-net-run to generate cache on x86 host.

Follow the instructions below to download the model and un-tar it. If you have already performed this setup, these commands can be skipped.

$ cd $QNN_SDK_ROOT/examples/QNN/TFLiteDelegate/Models/InceptionV3Quant/
$ wget https://storage.googleapis.com/download.tensorflow.org/models/tflite_11_05_08/inception_v3_quant.tgz
$ tar -xvzf inception_v3_quant.tgz

There should be a file called inception_v3_quant.tflite in the directory. This is the model that will be used to generate cache.

Running the Offline Preparation on Linux development host¶

Run the following command to generate the cache of the inception_v3_quant model. Checkout the tools:qd-graph-prepare page for a reference on all the supported command line options.

$ export LD_LIBRARY_PATH=$QNN_SDK_ROOT/target/x86_64-linux-clang/lib/:$LD_LIBRARY_PATH &&
             $QNN_SDK_ROOT/target/x86_64-linux-clang/bin/qd-graph-prepare \
             --model $QNN_SDK_ROOT/examples/QNN/TFLiteDelegate/Models/InceptionV3Quant/inception_v3_quant.tflite \
             --cache_dir $QNN_SDK_ROOT/examples/QNN/TFLiteDelegate/
             --htp_socs sm8550

There should be the cache file in $QNN_SDK_ROOT/examples/QNN/TFLiteDelegate/. The output should look something like the following. If there are any errors revisit the instructions above or checkout Generate Model Cache or Restoring from One to get more details about the cache files.

Running the Inference on device¶

After qd-graph-prepare has completed running, the prepared model will be saved to these file which is created by |Qualcomm(R)| AI Engine Direct Delegate, if --cache_dir exist. Next, these all cache files can be pushed to the device.

If caching data exist, its console output would indicate caching is operating in RESTORE MODE.

For now, follow the Tutorial for qtld-net-run to restore the cache when running the inception_v3_quant.

Run the following command to push cache to the device.

$ adb shell mkdir -p /data/local/tmp/qnn_delegate/cache/
$ adb push $QNN_SDK_ROOT/examples/QNN/TFLiteDelegate/*.bin /data/local/tmp/qnn_delegate/cache/

Run the following command to execute inference using the cache files with qtld-net-run. Give the correct path with the --cache_dir to the tools:qtld-net-run. Checkout the tools:qtld-net-run page for a reference on all the supported command line options.

Note that if --cache_dir exist and caching data doesn’t exist, model caching will operate in SAVE MODE, meaning the prepared model will be saved to these files such as offline preparation.

$ adb shell 'export LD_LIBRARY_PATH=/data/local/tmp/qnn_delegate/:$LD_LIBRARY_PATH &&
             export ADSP_LIBRARY_PATH="/data/local/tmp/qnn_delegate/" &&
             cd /data/local/tmp/qnn_delegate/inception_v3_quant/ &&
             /data/local/tmp/qnn_delegate/qtld-net-run \
             --model inception_v3_quant.tflite \
             --input input_list.txt \
             --cache_dir /data/local/tmp/qnn_delegate/cache \
             --output output \
             --backend htp'
