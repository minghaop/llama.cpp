Tutorial #5: Build |Qualcomm(R)| AI Engine Direct Delegate API with your own TFLite Version¶

|Qualcomm(R)| AI Engine Direct Delegate is built with a certain TF version. But sometimes, clients might need newer TF. One possible problem is, the ABI compatibility can be broken between new TFLite runtime and the Delegate SDK pre-built with older TFLite.

To resolve this problem, we experimentally split out Delegate core from TFLite, releasing a pre-built libqnn_delegate_core.so and some adaption codes. They are files under <sdk>/src.

This tutorial aim to describe steps for clients using new TF instead of the version which the Delegate SDK is built and tested with.

Currently only C-API interfaces can be built by this approach.

Step 0: Set up building environment¶

We can refer to Build TensorFlow Lite for Android to set up the environment, including Bazel, Android NDK, and Android SDK.

We strongly recommend to use the same NDK to ensure compatibility. At the moment of writing this tutorial, it’s 19c(Refer to above TFLite official website.)

Step 1: Prepare files¶

Create a directory, for example qnn, under <tensorflow_root>/tensorflow/lite/delegates/, and copy everything in <qnn_delegate_sdk_root>/src/ to the directory. We can see a structure like

<tensorflow_root>/tensorflow/lite/delegates/qnn/
├── BUILD
├── prebuilt
│   └── aarch64-android
│       └── libqnn_delegate_core.so
├── qnn_delegate.h
├── qnn_delegate_impl.h
├── qnn_delegate_interface.h
├── qnn_delegate_tflite.cc
└── qnn_delegate_tflite.h

Then we are ready to go.

Step 2: Building the |Qualcomm(R)| AI Engine Direct Delegate Shared Library with Your TFLite version¶

Go to <tensorflow_root>, and issue the command:

bazel build -c opt --config=android_arm64  tensorflow/lite/delegates/qnn:libqnn_delegate_api.so.stripped

Then we can find libqnn_delegate_api.so.stripped under <tensorflow_root>/bazel-bin/tensorflow/lite/delegates/qnn/.

Note that the suffix stripped is a Bazel convention for a stripped share library. We can rename the stripped library to what we what, maybe just libqnn_delegate_api.so.

Step 3: Use the compiled |Qualcomm(R)| AI Engine Direct Delegate API Shared Library¶

It’s quite similar to how we use C-APIs from libqnn_external_delegate.so. The only thing to note is, while we are building applications, we should tell the linker to link both libqnn_delegate_api.so and libqnn_delegate_core.so because some APIs are still provided by libqnn_delegate_core.so.

Note

We won’t need libqnn_external_delegate.so if this approach is chosen. Please don’t mix them.

For example, we can create a directory <awesome_project>, put libqnn_delegate_api.so.stripped and libqnn_delegate_core.so there. Then we rename libqnn_delegate_api.so.stripped to libqnn_delegate_api.so.

So, for example cmake is used in <awesome_project>, we need following commands in CMakeLists.txt:

add_library(qnn_delegate_core SHARED IMPORTED)
set_property(TARGET qnn_delegate_core PROPERTY
    IMPORTED_LOCATION "${PROJECT_SOURCE_DIR}/libqnn_delegate_core.so")

add_library(qnn_delegate_api SHARED IMPORTED)
set_property(TARGET qnn_delegate_api PROPERTY
    IMPORTED_LOCATION "${PROJECT_SOURCE_DIR}/lib/libqnn_delegate_api.so")
# ...
target_link_libraries(<target_name> PRIVATE qnn_delegate_api qnn_delegate_core <....>)
